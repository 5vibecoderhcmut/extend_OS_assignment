# Topic 3: Deadlock Detection using Wait-for Graph

This project implements the deadlock detection simulator in **C**. The C programs parse CSV datasets, simulate resource ownership and waiting relationships, build the Wait-for Graph, detect cycles with DFS or BFS/Kahn's algorithm, and export the experiment metrics to CSV.

Python is used **only** for visualization after the C experiment runner has created the CSV result files. It does not implement the simulator, Wait-for Graph construction, DFS/BFS algorithms, or metric collection.

The shared C header is stored in `include/deadlock_core.h`. The Makefile passes `-Iinclude` through `CPPFLAGS`, so source files keep the portable include directive `#include "deadlock_core.h"`.

## Project structure

```text
.
├── datasets/                    # 4 scale groups, 5 pseudo-random CSV files per group
│   ├── small/
│   ├── medium/
│   ├── large/
│   └── very_large/
├── scripts/
│   └── plot_results.py          # CSV-to-PNG visualization only
├── include/
│   └── deadlock_core.h          # shared C interfaces and data structures
├── src/
│   ├── deadlock_core.c          # CSV reader, simulator, WFG, DFS, BFS/Kahn
│   ├── deadlock_simulator.c     # single-dataset command-line trace tool
│   └── run_experiments.c        # batch C experiment runner and group summaries
├── Makefile
└── run.sh
```

```

The figures are generated by a Python script after the C experiments complete:

```

No `pandas` package is required.

## Run experiments

```bash
make all
```

or:

```bash
./run.sh
```

The C runner processes every dataset using DFS and BFS, with:

```text
K values : 1, 2, 5, 10
Repeats  : 5 timing runs per configuration
```

The five timing runs are averaged internally. The result CSV therefore has one row per:

```text
1 dataset × 1 algorithm × 1 detection interval K
```

The command creates:

```text
results/
├── experiment_results.csv
├── group_summary.csv
└── experiment_config.json
```

`group_summary.csv` has the same output columns as `experiment_results.csv`, but it averages the numeric metrics across the five datasets in each group: `small`, `medium`, `large`, and `very_large`.

## Generate plots

Run this only after `make all`:

```bash
make plot
```

The Python plotting script reads the CSV files produced by the C runner and creates:

```text
plots/
├── latency_vs_k_by_group.png
├── overhead_vs_k_by_group.png
├── frequency_vs_k_by_group.png
├── detection_time_by_group_dfs_bfs.png
├── overhead_by_group_dfs_bfs.png
└── detection_time_vs_edges.png
```

The first five figures use the group-level averages. `detection_time_vs_edges.png` uses individual dataset rows to show that detection time depends on Wait-for Graph density as well as process count.
